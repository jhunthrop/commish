# web

The Commish prep site: one SvelteKit app (Svelte 5 runes, TypeScript strict) on Cloudflare Workers
static assets through `@sveltejs/adapter-cloudflare`. Nightly pages are prerendered at build. User
pages are client-rendered and talk to the Go API. The spec is
`docs/superpowers/specs/2026-10-12-prep-site-architecture-design.md`, section 2.1.

This folder has its own `package.json`. The repository root's is the Next.js app being retired.

## Run

```sh
cd web
npm install
cp .env.example .env   # the run to build from: latest, from the local .runs/ folder
npm run standin        # writes the stand-in run into .runs/ (needs the compose dev database)
npm run dev            # http://localhost:5173, the board at /board, the system page at /system
```

## The run

Every nightly page (boards, players, ADP, the record, clubs, schedule, compare, search) is
prerendered at build from one nightly run (spec §2.1, §4). Two build inputs choose it, so a new run
needs no code change:

- `PUBLIC_RUN_ID`: a run id such as `2026-10-12T05`, or `latest` for the run `runs/latest.json` names.
- `PUBLIC_RUN_BASE_URL`: the folder holding `runs/`. Locally a directory (`.runs`). In CI the R2
  bucket's S3 endpoint, with `R2_ACCESS_KEY_ID` and `R2_SECRET_ACCESS_KEY` derived from
  `CLOUDFLARE_API_TOKEN` by `scripts/r2-env.ts`, so the bucket stays private.

The format is `src/lib/run/schema.ts`, one zod schema per artifact under `runs/<runId>/`:
`manifest.json`, `boards/<format>.json` (format ids like `ppr-12`), `players/<id>.json`, `adp.json`,
`record.json`, `index.json`, `clubs.json`, `schedule.json`. The build validates every artifact and
fails naming the file and field, so a malformed run never deploys. A run's writer uploads its
folder, moves `runs/latest.json` last, and dispatches the `nightly-run` event with the run id.

Every basis a page prints comes from the run: ADP's drafts and their window, schedule strength's
method and the date its inputs were read, the record's statistic, method and frozen runs. The
manifest's `sources` block names each feed's vendor and window as provenance; no screen shows it.

`scripts/run-from-mock-data.ts` (`npm run standin`, `-- --upload` to put it in R2) is the stand-in
until the first real run: the approved mocks' 2026 board and capsules, plus the dev database's
preseason ADP captures, 2026 slate, published win totals and register state.

### At cutover

- Delete `scripts/run-from-mock-data.ts` in the change that moves `runs/latest.json` to the first
  real run, so nothing in `web/` reads `research-ts/` or the dev database once `src/` and the
  oracle are gone.
- The Worker is `commish-web`; the custom domain route on `trycommish.app` is added to that name.

## Build and gates

```sh
npm run check          # wrangler types, svelte-kit sync, svelte-check
npm run lint           # Prettier, then ESLint with typescript-eslint strictTypeChecked
npm run build          # wrangler types, then vite build into .svelte-kit/cloudflare
npm run preview        # the built Worker under wrangler dev at http://localhost:4173
npm run preview:static # the build as production serves it, with the headshot route, at :4173
npm run lighthouse     # Lighthouse CI against preview:static, budgets in lighthouserc.cjs
npm run screenshots -- http://localhost:4173/board/ppr-12 board   # both themes at 1440 and 390, into screenshots/
```

`worker-configuration.d.ts` is generated by `wrangler types` on every check and build and is not
committed: once a build exists, wrangler adds a type import of the built worker to it, so a
committed copy goes stale after the first build. `checkJs` is off for the same reason, so the built
worker's JavaScript is never type-checked as if it were ours. Everything we write is TypeScript.

## Running Lighthouse locally

1. Build first. The audited pages come from `.svelte-kit/cloudflare`, so a stale build audits stale
   pages: `npm run standin && npm run build`, or the build the nightly run makes.
2. Pick a free port and use it for both the server and the configs: `PORT=4601 npm run lighthouse`
   (the default is 4173). `lighthouserc.cjs`, `lighthouserc.sheet.cjs` and `scripts/serve-built.ts`
   read the same `PORT`.
3. Leave the machine quiet. The runs are timed with devtools throttling and a 4x CPU slowdown.

A run that is bimodal, with first paint equal to LCP at about 0.67 s on most runs and at 1.66 s or
2.67 s on others, script bytes unchanged, is the harness and not the page. The cause found in Lane 49
is Chrome's paint holding. On a large document (the board's HTML is 1.4 MB) Chrome holds the first
commit until the parse finishes, the web fonts are requested at that moment, and the text is not
painted until they arrive, so the paint lands one or two seconds late depending on how the font
requests queue behind the headshots. `--disable-features=PaintHolding`
(`lighthouse-shared.cjs`) removes it. It was not `localhost` resolution, the service worker, the
static server or machine load. If the steps return, check that the flag still reaches Chrome before
anything else.

## Budgets

`lighthouserc.json` carries the spec's budgets at the mobile profile (150 ms round trip, 1.6 Mbps,
4x CPU), applied throttling, nine runs, asserted on the median. Chrome's paint holding used to land a run's first paint at 0.67 s, 1.66 s or 2.67 s on some machines whatever the page (see Running Lighthouse locally), which on 2026-10-13 failed a seven-run median on noise. Both configs now turn it off, so the runs agree. Nine runs stay as margin, and the 1.2 s budget is unchanged. Prerendered pages are measured from `npm run preview:static` (`scripts/serve-built.ts`), a compressing static server over the build that also answers the headshot route, because in production they are Workers static assets with no Worker in the path. Prerendered pages: LCP 1.2 s, script
transfer 60 KB as the target and 72 KB as the deploy gate (the Svelte and SvelteKit client runtime is a 47 KB floor before any page code; a page over 60 is a review finding, over 72 fails the deploy). User pages (sheet, mock, lobby, report, account, pass): LCP 2.0 s, script 180 KB.
CLS 0.05 everywhere. Collected: the board, a player page and the record. The system page is a noindex documentation page, not a nightly page, and is not held to the nightly budget.
`.github/workflows/web.yml` runs check, lint, the timed build (budget four minutes), Lighthouse and
the deploy to the workers.dev preview, on a push to main touching `web/` and on `nightly-run`.
The workers.dev address is also where Disney's ESPN sign-in runs (`src/lib/site/origins.ts`), so it
must stay on. Local dev (`npm run dev`, `npm run preview`) and preview-version URLs cannot finish
Disney's sign-in: the window opens on the production workers.dev address and hands the two ESPN
values to `https://trycommish.app` only, so another origin never receives them. Connect ESPN there
falls to the paste form, which works anywhere.

The client loads the Svelte runtime and the components four or more routes share as two files
(`vite.config.ts`), which keeps a nightly page's script requests near ten and under the budget. Only
styles are preloaded (`hooks.server.ts`): preloaded fonts made Chrome hold a light page's first
paint until they landed, so a page paints in the fallback face at once and swaps when the fonts
arrive. The swap costs a CLS of about 0.035 against the 0.05 budget.

## Tokens and primitives

`src/lib/ui/tokens.css` is the token set of the approved design authority,
`docs/design/mocks/2026-10-12-commish/tokens.css`, copied verbatim in the same three blocks: light on
bare `:root`, dark under `prefers-color-scheme` guarded by `:root:not([data-theme="light"])`, and
dark again under `:root[data-theme="dark"]`. Change a token there first, then here.

The primitives in `src/lib/ui/` port the mock's `build/shell.py` and `build/roomparts.py`, one
component per file with typed props. Every color is a token, and no page styles a primitive from the
outside. The system page at `/system` renders each of them with the mock's real 2026 PPR rows from
`src/fixtures/mock-2026-ppr.ts`, the only fixture in the app.

## Fonts

Google Fonts' Outfit and Big Shoulders Display for the UI, Newsreader for capsule prose, all
self-hosted from the Fontsource packages of the same files so the first paint never waits on a
cross-origin stylesheet. `scripts/subset-fonts.ts` (`npm run fonts`) cuts the two UI faces to Basic
Latin, Latin-1 Supplement and Latin Extended-A plus curly quotes, the ellipsis, the minus and the
arrows, the list in `src/lib/ui/fonts/coverage.ts`, and writes `src/lib/ui/fonts/ui.css` and
`src/lib/ui/fonts/core/`. Commit its output. Any other character falls through to the full Latin
files, which load only when needed.

`npm run build` runs the glyph guard first (`scripts/check-glyphs.ts`, also `npm run glyphs`): every
player name the pages render, today the fixture and later the nightly run's `index.json`, must sit
inside that same list, or the build fails naming the first glyph outside it. Widen `coverage.ts` and
rerun `npm run fonts` when a real name needs it.

`src/lib/ui/fonts/read.css` holds Newsreader and is imported only by a component that sets prose.

## Headshots

Faces load from our origin: `/img/headshots/<league>/<id>/<width>` (the one request-time route)
fetches the drawn size from the provider once and keeps it at the edge for a week. A face asks for
its drawn width at 1x and 2x, about 10 KB instead of the 260 KB original. The provider is the one
line in `upstreamHeadshotUrl` (`src/lib/ui/headshot.ts`).

## The sheet

`/sheet` and `/sheet/print` are user pages: the frame is prerendered and the sheet is drawn in the
browser. Everything lives in `src/lib/sheet/`. The sheet works signed out from `localStorage`
(`storage.ts`) and saves to the account through the API when signed in (`sync.ts`, the merge rule
in `merge.ts`). `PUBLIC_API_URL` names the API at build: production by default,
`http://localhost:8080` for a local API. Our board reaches the sheet as
`data/sheet-board/<format>.json`, written at build from the run by `src/lib/server/sheet-board.ts`
(the run's `ppr-12` board is the sheet's `ppr`).

Mount points for other lanes: `SheetRail.svelte` in the board's side column, `AddToSheet.svelte`
(variant `verb` on the player page, `row` on a board row), `SaveDraftAsSheet.svelte` on the mock
report, and `sheetStore.queueFor(available)` with `QUEUE_SEED_SIZE` in `queue.ts` for a room's
queue.

`npm run measure:sheet -- <url>` measures the drag at the phone profile with a mouse and with a
finger (touch, a cancelled touch, a pan), a 400-row import and the print view against a running
build. `npm run lighthouse:sheet` (part of `npm run lighthouse`) audits `/sheet` with 400 rows
seeded into the browser before each cold run (`lighthouserc.sheet.cjs`,
`scripts/lighthouse-seed-sheet.cjs`); `LH_SHEET_URL` points it at a build already being served.

The paper tokens (`--paper`, `--paper-ink`, `--paper-line`, `--paper-muted`) are this lane's
addition to `tokens.css`: the print view's colors in both themes, and the page ground under print
media.
