# Tank01 coverage audit — 2026-08-30

Founder ask: "do an audit and ensure we're capturing all tank01 fields and apis."
Method: a field-by-field inventory of our integration (`src/stats/tank01/`, `src/projections/capture-feeds.ts`)
diffed against the live RapidAPI endpoint catalog (verified 2026-08-30 from the listing's embedded
endpoint JSON, tank01.com guides, and live-verified community code).

## Verdict in one paragraph

Tank01 offers **21 endpoints; we call 11**. Of the 11, four are parsed into product tables and
seven are captured as raw snapshots that **nothing ever reads**. On the endpoints we do parse, we
discard fields with direct product value — most notably the box score's `snapCounts`, `targets`,
`carries`, and `ptsAllowed` (so our DEF scoring silently omits the industry-standard
points-allowed tiers). The largest misses are whole endpoints: **weekly fantasy projections**
(`/getNFLProjections`, custom scoring supported), the **cheap live-score poll**
(`/getNFLScoresOnly`), and the **dedicated injuries feed** (`/getNFLInjuriesByDate`) — the exact
three the live-season product needs.

## 1. Endpoints we never call (10 of 21)

| Endpoint | What it is | Why it matters to Commish |
|---|---|---|
| `/getNFLProjections` | Weekly + season fantasy projections, custom scoring via query params, `archiveSeason` to 2023, ~hourly | The Proj column (ESPN-parity), advisor grounding, FA board ranking beyond ADP |
| `/getNFLScoresOnly` | Live scoreboard, statuses only, cheap | The polling primitive for the live-season loop (detect `gameStatusCode=1`, then box-score only live games) |
| `/getNFLInjuriesByDate` | Dedicated injury list by date (new endpoint) | Q/O/IR tags on every roster surface — we show no injury status anywhere today |
| `/getNFLInactiveList` | Weekly inactives (2026+ only) | The Sunday-morning "your starter is inactive" alert |
| `/getNFLCurrentInfo` | Current season/week from the source | Authoritative NFL week; today we infer from `stat_weeks` |
| `/getNFLPlayerInfo` | Bio + injury for one player | Player page depth (college, exp, birthdate) |
| `/getNFLGamesForPlayer` | Game-by-game log, `season` back to 2022 | Player-page game log; the clean route to a 2025 historical backfill |
| `/getNFLTeamSchedule` | One team's season schedule | Bye-week cross-check for `nfl_games` |
| `/getNFLGamesForDate` | Day's schedule by `gameDate` | Live-day gameID discovery |
| `/getNFLGameInfo` | One game's basics | Minor; covered by `nfl_games` |

## 2. Fields we fetch but discard (endpoints we call)

- **`/getNFLBoxScore`** — we read the 15 stat keys our `StatLine` needs and drop:
  `snapCounts{offSnap, offSnapPct, defSnap, defSnapPct, stSnap, stSnapPct}` (pre-computed snap
  percentages), `Receiving.targets`, `Rushing.carries`, `Passing.passAttempts/passCompletions`,
  `Kicking.fgAttempts`, `longRec`, and — the scoring-fidelity bug — **`DST.ptsAllowed`**, so
  DEF scoring is sacks/INT/TD only, no points-allowed tiers. We also never pass
  `fantasyPoints=true` (their PPR/half/standard defaults + custom-scoring echo would be a free
  cross-check against our scoring engine) or `playByPlay=true`.
- **`/getNFLPlayerList`** — drop `jerseyNum`, `isFreeAgent`, `teamID`; community code reports
  cross-platform IDs (espnID, sleeperBotID, …) in this payload — unverified, worth one live call,
  and directly useful to `player_crosswalk`. `espnHeadshot` is read by our mapper but appears in
  **no fixture** — unverified against the live API.
- **`/getNFLADP`** — drop `posADP` ("RB1"-style position rank, a draft-room natural), `adpDate`.
  We only ever request `adpType=PPR`; halfPPR/standard/bestBall exist for future league types.
- **`/getNFLTeams`** — drop records, streaks, points for/against, logos.
- **`/getNFLGamesForWeek`** — drop `teamIDWin`-adjacent metadata (minor); our mapper's
  `gameStatuses.in_progress` list is decorative (fall-through), and Tank01's numeric
  `gameStatusCode` (0 not-started / 1 live / 2 final / 3 postponed / 4 suspended) is unused — we
  cannot represent postponed/suspended today.

## 3. Captured raw, consumed by nothing (7 feeds)

`capture_snapshots` holds tank01_injuries (11MB — full 32-roster sweeps with per-player injury
objects), depth_charts, news, betting_odds, dfs_salaries, changelog, adp — written on cadence by
`captureOnce`, read only by the dedupe digest. **Zero product or model consumers.** The injury
data the product lacks is already on disk, unparsed. (`news/retrieve.ts` deliberately uses
nflverse injuries for the archive property — that reasoning holds for history, not for the
current-designation surface the product needs.)

## 4. Housekeeping findings

- No fixture has ever been recorded from the live API (`manifest.json` provenance:
  `authored-from-published-response-shapes`, `recordedAt: null`); six config paths are flagged
  UNVERIFIED in `config.ts`. One `scripts/record-tank01-fixtures.ts` run closes this.
- Historical reach if we backfill 2025: schedules/game stats to 2022, projections to 2023,
  rosters to 2023-05, odds to 2023-08, DFS to 2025-01, ADP to 2024-04; inactives 2026+ only.
- Client discards the envelope's `statusCode`; error taxonomy otherwise sound.
- Budget: 14,313 requests remain this month — none of the above is budget-constrained.

## 5. Recommended sequence

1. **Injuries to the product** — parse the snapshots we already hold + adopt
   `/getNFLInjuriesByDate`; injury tags on lineup/FA/draft rows. Highest UX value per request: ~1/day.
2. **Weekly projections** — `/getNFLProjections` with our scoring in the query; Proj column in
   the lineup editor (the last ESPN-parity gap), advisor grounding. ~1/hour at most.
3. **Live loop** — `/getNFLScoresOnly` poll + `fantasyPoints=true` box scores; widen `StatLine`
   (targets, carries, snaps, **ptsAllowed** → fix DEF scoring) while we're in the mapper.
4. **Verification pass** — record live fixtures, confirm `espnHeadshot` + cross-platform IDs +
   `fantasyPoints` vs `fantasyStats` param naming (one call each).
5. **2025 backfill decision** — `/getNFLGamesForWeek?season=2025` + box scores (community-verified
   to work) to replace the fabricated dev stat lines, per the no-mock ruling.
