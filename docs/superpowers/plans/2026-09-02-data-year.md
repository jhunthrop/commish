# Data Year Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The prospective register frozen-before/graded-after all season, one weekly command running the whole cadence, scheduling in place before the 2026-09-10T00:15Z kickoff, and the debt that bites during a long season paid down.

**Architecture:** A register store that is an archive by construction (append-only freezes keyed by instant), a grading pass structurally walled off from everything that prices or selects, one orchestrating weekly script over existing ingest/snapshot machinery, and a small ops task set (cleanup, read assertion, tmpfs).

**Tech Stack:** TypeScript, Postgres/Drizzle, vitest (serial only), the existing nflverse + odds machinery; local cron for cadence.

**Spec:** `docs/superpowers/specs/2026-09-02-data-year-design.md`

## Global Constraints

- ONE vitest runner, `--no-file-parallelism`, halves for wide runs. No em-dashes printed/rendered. Tri-state. Figures from runs. THE QUARANTINE WALL: no fit, law, board, or blend path imports the register; pinned by test. THE FREEZE GUARD untouched; the register never writes board tables. Freezes strictly before the week's first kickoff (refused otherwise); frozen rows immutable (supersede by new freeze instant only). Lean reviews except the quarantine wall (focused leakage read). Deadline: the machine runs before 2026-09-10T00:15Z.

### Task 1: The register

**Files:**
- Create: migration + `src/projections/register/store.ts` (freeze rows: season, week, freeze instant, player id, board points/value stance from the SERVED v7 board read path, adp/ecr/props benchmark columns tri-state; graded rows: keyed to the freeze they grade, actual points, per-column ranks/errors)
- Create: `src/projections/register/freeze.ts` (take a freeze: reads the served board via the product read path + current benchmarks + the week's props consensus from the odds archive; REFUSES at-or-after kickoff via `firstKickoffFor`-per-week) and `register/grade.ts` (grade a completed week from ingested stats; writes graded rows + prints the running scoreboard)
- Test: TDD freeze refusal at/after kickoff, immutability (a second freeze same week = new instant, old rows untouched), tri-state benchmarks, grading correctness on fixtures, and THE WALL (a structural test that no src/projections/{market,laws,model,preseason} module imports src/projections/register)

**Interfaces:**
- Consumes: the product board read (`preseasonProjectionsAsOf` under BOARD_SOURCE), rankings, props archive, stat lines, week kickoffs. Produces: the register tables and the scoreboard print. NOTHING consumes the register outside register/ and its scripts.

- [ ] Steps: TDD -> implement -> migration dev+test -> serial suites -> take a REAL week-1 freeze (before kickoff; paste counts and the freeze instant) -> commit `feat(register): the prospective register freezes before kickoff`.

### Task 2: The weekly cadence

**Files:**
- Create: `scripts/season-week.ts` (npm `season:week`): stats-ingest-if-published -> props snapshot -> grade-last-week-if-gradeable -> freeze-this-week-if-before-kickoff -> scoreboard; each step idempotent, reporting did/skipped/why, credits printed for the props step
- Create: the cron installation (a documented `scripts/install-season-cron.sh` writing two crontab entries: a mid-week data pass and a pre-kickoff freeze pass, times chosen from the schedule's own kickoff patterns) + the runbook section for manual runs
- Test: orchestration on fixtures (step skipping, idempotency); no network in tests

**Interfaces:**
- Consumes: Task 1 + existing scripts. Produces: the one command, the cron entries, the runbook.

- [ ] Steps: TDD -> implement -> run `npm run season:week` for real once (expect: stats skip (none published yet), props snapshot real, grade skip (nothing gradeable), freeze skip-or-supersede honestly per Task 1's real freeze, scoreboard prints) -> paste output -> install the cron for real, paste `crontab -l` -> commit `feat(ops): one command runs the season week`.
