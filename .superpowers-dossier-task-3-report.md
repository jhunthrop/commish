### CallCard

Props:
```ts
interface CallCardMarket { adp: number | null; expertRank: number | null; }
interface CallCardOurBoard { position: Position; positionRank: number | null; boardRank: number; points: number; perGameRank: number | null; expectedGames: number | null; }
interface CallCardProps { verdict: string | null; market: CallCardMarket; ourBoard: CallCardOurBoard; gap: number | null; }
```
`market`/`ourBoard` are deliberately narrower than the full `PlayerFactsMarket`/dossier projection — only the fields the mock's three columns actually print — so a Task 5 composer builds them from `PlayerDossierFacts.market`/`.projection`/`.availability` plus a `verdictLine(reasons, position)` call it makes itself (this component states the verdict, it does not derive it, per the coordinator's brief).

Rendering:
- Verdict sentence (when non-null) and the gap column ("+20"/"-20"/"0 points vs his price", or "Not priced by the market." when `gap` is `null`) both carry the SAME verdict-channel tone — `text-positive`/`text-negative`/`text-text-muted` (null or exact zero) — since they state the identical fact twice, prose then number. Reused `EdgeCell`'s own doctrine (sign printed, never color-only; a zero or absent gap takes no tint) rather than inventing a second one.
- Column 1: "pick {adp} · experts {expertRank}th" (`ordinal`, `../lib/format`, the same helper `grade-board.tsx` uses), `NOT_STARTED_DASH` for either half when null.
- Column 2: `PositionBadge` (POS+rank sticker, `@/components/ui`) followed by "· {boardRank}th overall · {points} pts".
- Talent-vs-games sentence: "Per game he projects like a {POS}{perGameRank}. The question is games: our model expects {expectedGames rounded}." — rendered only when both `ourBoard.perGameRank` and `ourBoard.expectedGames` are non-null.

### RangeRail

```ts
type RangeRailProjection = Pick<PlayerFactsProjection, "floorPoints" | "medianPoints" | "ceilingPoints" | "typicalLow" | "typicalHigh">;
interface RangeRailProps { projection: RangeRailProjection; availability: PlayerFactsAvailability | null; }
```
Five points (floor whisker, band start, median tick, band end, ceiling whisker) positioned by a shared `railPct(value, floor, ceiling)` helper (0..100, degrades to 50 when `ceiling <= floor` rather than dividing by zero), each carrying a `data-rail-point` attribute and an inline `style.left`/`style.width` percentage for direct assertion. Labels: "an injury year" / "most seasons land in the band · {median} is our number" / "the smash case". `text-accent` is spent ONLY on the printed median number, never as a fill on the tick itself (no `bg-accent`, so no accent-budget allowlist entry needed). The expected-games chip ("Expected {n} games, weeks {floorGames} to {ceilingGames}") renders only when `availability !== null`.
