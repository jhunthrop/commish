## `PlayerDossierFacts` — exact top-level fields

```ts
interface PlayerDossierFacts {
  market: PlayerFactsMarket;
  projection: PlayerDossierProjection; // PlayerFactsProjection + perGamePoints, perGamePositionRank
  availability: PlayerFactsAvailability | null;
  usage: PlayerFactsUsage | null;
  trend: PlayerFactsTrend | null;
  books: PlayerFactsBooksNumbers;       // renamed from PlayerFacts.booksNumbers
  lastSeasonStory: PlayerFactsLastSeasonStory | null;
  injury: PlayerFactsInjuryStatus;
  newsCount: number;                    // count only, not the headlines (PlayerSeasonBody.news already carries those)
  basis: { boardGeneration: string; scoringLabel: string };
}
```

`PlayerDossierProjection` = `PlayerFactsProjection` (`projectedPoints`, `floorPoints`, `medianPoints`, `ceilingPoints`, `typicalLow`, `typicalHigh`) plus:
- `perGamePoints: number | null` — `projectedPoints / expectedGames`, `null` when `expectedGames <= 0` or the board never ranked him.
- `perGamePositionRank: { value, positionRank, qualifierCount } | null` — `PlayerDossierRank`, a trimmed `RankedStat` (no `namedNeighbor`: nothing renders a per-game neighbor name, so nothing looks one up).

Deliberately excluded from `PlayerFacts` (the validator's own vocabulary, not client-facing): `evidence`, `numberLedger`, `nameLedger`, `factsHash`, `identity`, `productSeason`, `byeWeek` (the last two are already answered elsewhere on `PlayerSeasonBody`).

## Per-game rank derivation

One additional whole-board read, `preseasonProjectionsAsOf(db, {season, source: BOARD_SOURCE, asOf})`, plus the same `allPositions(db)` helper Task 1's `collect-one.ts` already runs for the identical "who else plays his position" question. Every row's own `expectedGames`/`projectedPoints` yields a per-game rate; rows with `expectedGames <= 0` are excluded from the ranked population (no evidence, no fabricated rate). Ranking reuses `rankWithinGroups` (`@/capsules/rank`) unchanged — the same tested algorithm every other rank in this product uses, grouped by position from `allPositions`. Exactly one whole-board query for this purpose; the target player's own value comes out of the identical pass rather than a second lookup.

## `boardGeneration` and `scoringLabel`

- **`boardGeneration`** resolved to `rows[0]!.asOf.toISOString()` off the SAME `preseasonProjectionsAsOf` pass used for the per-game rank — the exact formula `draft-service/sim/evidence.ts`'s `evidencePoolFor` uses for its own `EvidencePool.boardGeneration` (`assertSingleGeneration`'s invariant: every row under one live generation shares one `asOf`). Deliberately NOT calling `evidencePoolFor` itself: that function pays for its own separate whole-board read plus a crosswalk join and market-rank pass this dossier has no use for — calling it would be the "second whole-board read" the task said to avoid. `src/draft-service` was read (to learn the derivation), never modified.
- **`scoringLabel`** resolved via `describeScoring(PPR_SCORING)` (`@/scoring`, re-exported from `scoring/describe.ts`) → `"PPR"`. `PPR_SCORING` is the same fixed format `collect.ts`'s `currentSeasonSummaries` docblock names and the shipped board is composed under — read from the real config object, not a hardcoded string, so a change to the product's default format changes this label for free.
